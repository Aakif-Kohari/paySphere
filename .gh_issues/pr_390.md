## Description

This PR refactors the audit logging mechanism into an Event-Driven Architecture, significantly improving API response times for write-heavy endpoints.

Previously, `createAuditLog()` was called synchronously in multiple controllers, forcing the main thread to wait for a database insert before returning a response to the user. This PR introduces an `EventEmitter` bus, allowing controllers to dispatch `AUDIT_LOG` events in a fire-and-forget manner while a dedicated background listener handles the database inserts asynchronously.

### Architectural Changes:
1. **Event Bus:** Created `backend/src/services/event.service.js` which exports a Node.js `EventEmitter`.
2. **Audit Listener:** Created `backend/src/listeners/audit.listener.js` to process incoming `AUDIT_LOG` events and insert records into MongoDB.
3. **App Initialization:** Imported the listener into `backend/src/app.js` so it binds on server start.
4. **Controller Refactoring:** Replaced all synchronous `createAuditLog(...)` imports and calls with `eventBus.emit("AUDIT_LOG", ...)` across `employee.controller.js`, `payroll.controller.js`, `reports.controller.js`, and `user.controller.js`.
