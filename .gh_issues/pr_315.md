## Description

This PR fixes a critical security issue where logging out of the application did not invalidate the user's JSON Web Token (JWT). Previously, the `logout` controller only cleared the refresh token cookie. Because the access token is stateless and valid for 15 minutes, a hijacked token would remain fully functional even after the user explicitly logged out.

This PR updates the `logout` controller to decode the provided JWT (if present) and increment the user's `tokenVersion` in the database. Since the `auth` middleware already verifies that the token's version matches the user's current version, incrementing it immediately invalidates all existing access and refresh tokens for that user.

### Commands executed

* [ ] `npm test`
* [ ] `npm run lint`
* [ ] `npm run build`
* [x] Manual verification

### Manually verified

* Verified that `logout` successfully increments `tokenVersion` in the database.
* Confirmed that subsequent requests using the old access token fail with `401 Unauthorized` ("Token is no longer valid").

### Edge cases considered

* Calling logout without an `Authorization` header (e.g., cookie-only logout).
* Calling logout with an already expired token (using `ignoreExpiration: true` to still increment the version).
* Errors during token decoding are gracefully ignored to ensure the refresh token cookie is still cleared.
