## Description

This PR introduces a Redis caching layer to optimize the highly requested `/api/reports/analytics` endpoint. 

Previously, fetching payroll analytics and reports queried MongoDB synchronously on every request, creating a significant bottleneck for complex aggregations. This PR implements a generic caching service that intercepts read requests, falling back gracefully to in-memory caching if Redis is not configured in the environment.

### Architectural Changes:
1. **Cache Service:** Added `backend/src/services/cache.service.js` which handles Redis connections (`get`, `setEx`, `del`) with built-in retry logic.
2. **Controller Updates:** Refactored `reports.controller.js` to serve data from the cache using `analytics:${req.userId}:${monthsBack}` as the key.
3. **Cache Invalidation:** Added cache invalidation (`cacheService.invalidatePattern`) inside `employee.controller.js` and `payroll.controller.js` to aggressively clear stale data whenever an employee is added, updated, deleted, or payroll is finalized.
