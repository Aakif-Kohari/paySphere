## Description

This PR fixes a bug in the `deleteEmployee` controller where related `PayrollUpdate` records and the `Employee` record were deleted in two separate database operations without a MongoDB transaction. 

If the Node process crashed or the database encountered an error immediately after deleting the payroll records but before deleting the employee, the employee would remain in an inconsistent state (lacking all their historical payroll data).

This PR wraps the deletion of the `PayrollUpdate` records and the `Employee` record in an atomic MongoDB session transaction. If either operation fails, both are rolled back automatically, preventing orphaned or corrupt states.
