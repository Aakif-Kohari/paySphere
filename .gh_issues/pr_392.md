## Description

This PR migrates the highly CPU-bound `finalizePayroll` function from the main HTTP thread to an asynchronous background job queue using `bullmq` and `ioredis`. 

Previously, calculating salaries and inserting multiple MongoDB records for potentially hundreds of employees was handled synchronously, risking API timeouts and locking the main thread. Now, the endpoint dispatches a job and immediately returns a `202 Accepted` response.

### Architectural Changes:
1. **Queue Service:** Added `backend/src/jobs/queue.service.js` to initialize the Redis-backed BullMQ queue.
2. **Worker Process:** Added `backend/src/workers/payroll.worker.js` to pull jobs, process employee calculations, and use MongoDB transactions to save payroll updates safely.
3. **Controller Refactor:** Modified `finalizePayroll` in `payroll.controller.js` to dispatch the job and added a new `getPayrollStatus` endpoint.
4. **Route Update:** Added `GET /api/payroll/status/:jobId` in `payroll.routes.js`.

## API Documentation (required for any new/changed backend endpoint)

### `GET /api/payroll/status/:jobId`
Returns the current status of the payroll processing job.
**Response (200 OK):**
```json
{
  "state": "active", // "waiting", "active", "completed", "failed"
  "progress": 50 // 0-100%
}
```
