## Description

PaySphere had no distributed tracing, no request-level log correlation, and no liveness/readiness probes. There was no way to trace the request lifecycle when a payroll run was slow or a webhook failed.

**Fix:** Four new modules: tracer.js (OTel SDK bootstrap, gracefully no-ops without OTEL_EXPORTER_OTLP_ENDPOINT), spans.js (withSpan helper for child spans), correlation.middleware.js (unique X-Request-ID on every request/response, requestId injected into log context), health.controller.js + health.routes.js (GET /health/live, /health/ready, /health/metrics — mounted outside /api).

## Testing Performed

* All new files pass node -c syntax check.
* GET /health/live returns 200 { status: "ok", uptime }.
* GET /health/ready returns 503 when MongoDB is unreachable.
* Every response carries X-Request-ID header.
* initTracer() is a complete no-op when OTEL env var is unset.

### Edge cases

* OTel packages not installed: require() caught, warning logged, no crash.
* MongoDB unreachable on readiness: returns 503, does not throw.
* Redis unavailable: treated as non-critical, readiness still 200 if Mongo up.
* withSpan fn throws: exception re-thrown after recording on span.

## API Documentation

New endpoints (no auth required):
GET /health/live    -> { status: "ok", uptime: N }
GET /health/ready   -> { status: "ready"|"degraded", checks: { mongo, redis } }
GET /health/metrics -> Prometheus text exposition format

New .env variable (optional):
OTEL_EXPORTER_OTLP_ENDPOINT=http://localhost:4318
